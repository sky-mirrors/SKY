| 事实 | 位置 / 数量 |
|---|---|
| `npm test` **从不跑真机用例**——`test/e2e/**` 被显式排除 | `vitest.config.ts` 的 `exclude: ['test/e2e/**', ...]` |
| **30 个 spec 直接把 `electronAPI` 打桩**（`stubGlobal('window', ...)`）⇒ 真实文件系统 / IPC 边界在单测里是假的 | `grep -rl "stubGlobal('window'" test \| wc -l` = 30 |
| `test/e2e/` 下 3 个**独立 Electron 脚本**（不属 vitest），由 npm script 驱动 | `imagePipeline.e2e.ts` / `mediaPipeline.e2e.ts` / `pdfRender.e2e.ts` → `verify:image` / `verify:media` / `verify:pdf` |
| 3 个跑不起来的遗留 spec 已于 2026-10 删除 | `launch` / `l0Skill` / `stress.spec.ts`——依赖 `@playwright/test` 却从未在 `package.json` 声明，且被 vitest 排除，**从未跑过**（`stress` 的真实 LLM 压力场景转为手动手册） |

**结论**：`npm test` 全绿只证明「在打桩环境里逻辑自洽」，**不证明**真实场景可用。要真机证据得跑 `npm run smoke`（对话旅程）或 `npm run smoke:window-controls`（七个副窗的窗口控制）。

## 真机场景冒烟（`npm run smoke`）`[已复核：脚本存在 2026-10-08，6.9 KB]`

`scripts\scenario-smoke.mjs`——对**运行中的应用**（CDP `:9222`）跑真实用户旅程，断言可观察结果，失败非零退出；起跑先 `Page.reload` 归一 UI 状态。

五项断言：

1. 对话区默认不渲染系统通知
2. 列出文件（**真实读盘**）
3. 承接上文（命中上一轮结果）
4. 落盘写文件（**校验磁盘真实产物**）
5. 同会话记忆（隔 2 轮仍能回忆）

前置：应用已启动并开放 CDP 端口。

> ⚠️ **环境敏感点（2026-10-09 实测）**：脚本起跑固定 `Page.reload` + 等 6 s 归一状态。在**有大量历史会话数据的
> userData** 上（实测 26 条消息），6 s 不足以让消息区渲染完成 ⇒ 第 0 项断言
> （`.messages .message` 数量须 > 0）失败，并连锁使后续 `sendMessage` 在应用未就绪时发出，**5/5 全红**。
> 判据：会话结束后手工查 DOM，`.messages .message` 有 **7** 个、`.msg-system` 为 **0** —— **选择器正确，是等待时机问题**，
> 不是渲染缺陷（对照 `window-controls-smoke` 那次"字形硬编码导致假红"的教训，同类问题要先验选择器再改断言）。
> 另：不要在**另一个实例已占用 CDP 端口**时启动新实例——两者共享 userData，新实例的 devtools 端口会 bind 失败。

## 副窗窗口控制真机冒烟（`npm run smoke:window-controls`）`[已复核 2026-10-09：35/35 通过（七个副窗）]`

`scripts\window-controls-smoke.mjs`——对**运行中的应用**（CDP，默认 `:9333`；`CDP_PORT` 可覆盖）把**七个副窗**逐个开一次、点最小化、点关闭。**会在你正在运行的应用上真实开窗 / 最小化 / 关窗**；只处置**脚本自己新开的**窗——某窗此前已打开时直接跳过（不关你用着的窗）。`--only=packs,dev` 只跑指定窗，`--shots` 每窗落一张截图到 `.rivet\design\`。

每窗五项断言（都是可观察结果，不是「函数存在」）：渲染出窗口控制按钮（含最小化 ─ 与关闭 ✕）→ preload 对应 `xxxWindowMinimize/Close` 可调用 → 标题栏 `-webkit-app-region: drag` 生效 → 点最小化页面可见性转 `hidden` → 点关闭 CDP target 消失。

为什么单列：窗口控制是**只有真机才暴露**的缺陷面——`test\unit\ipcContract.spec.ts` 只能证明 preload 有键、main 有通道，**证明不了**「点下去窗口真的关」。2026-10 的真实缺陷正是这样漏过去的：`electron\main.ts:175-180` 注册了 `packs:window:*`，preload 一个键都没暴露，而该窗是 `frame:false` 无边框窗（`electron\window-manager.ts:332`）⇒ UI 内既关不掉也移不动；当时 vitest 与 typecheck 全绿。

**已知不一致（非缺陷，未改）**：最小化 / 最大化按钮的字形两套并存——packs / pipeline / rule-review / knowledge / dev 用 `─`(U+2500) + `□`(U+25A1)，debug / benchmark 用 `—`(U+2014) + `☐`(U+2610)，且后两窗的这两个按钮**没有 `title` 属性**。功能等价，但字形与渲染尺寸不同。脚本因此按字形集合识别（见脚本内 `MIN_CHARS` / `MAX_CHARS`）——**不要改回硬编码单字符**，那会把「按钮字形不同」误判成「按钮没渲染」而漏掉真实的按钮缺失。
