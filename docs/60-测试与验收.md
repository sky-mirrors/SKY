## 覆盖边界：全绿 ≠ 真机可用 `[已复核]`

| 事实 | 位置 / 数量 |
|---|---|
| `npm test` **从不跑真机用例**——`test/e2e/**` 被显式排除 | `vitest.config.ts` 的 `exclude: ['test/e2e/**', ...]` |
| **30 个 spec 直接把 `electronAPI` 打桩**（`stubGlobal('window', ...)`）⇒ 真实文件系统 / IPC 边界在单测里是假的 | `grep -rl "stubGlobal('window'" test \| wc -l` = 30 |
| `test/e2e/` 下 6 个文件长期休眠，无独立 runner 脚本 | `imagePipeline.e2e.ts` / `mediaPipeline.e2e.ts` / `pdfRender.e2e.ts` / `launch.spec.ts` / `l0Skill.spec.ts` / `stress.spec.ts` |
| 另有三个**单点真机 e2e** 通过 npm script 跑 | `verify:pdf` / `verify:image` / `verify:media` |

**结论**：`npm test` 全绿只证明「在打桩环境里逻辑自洽」，**不证明**真实场景可用。要真机证据得跑 `npm run smoke`。

## 加测试 / 改测试时

- 测试文件后缀是 **`.spec.ts`**（不是 `.test.ts`），放 `test\unit\`。
- 单跑一个文件：`npx vitest run test/unit/xxx.spec.ts`。
- 新增能力请同时更新本册的规模表与 [10-架构与分层](10-架构与分层.md) 的组件计数——数字过期是本项目历史上最反复出现的问题。
