# 机制边界总册与架构调和

> **定位**（2026-09-22 CHARTER 批，纯文档）：每个机制的边界章程——能解决什么、不能解决什么、边界如何界定、边界衔接给谁；以及编排架构如何调和边界冲突让它们咬合。
> **姊妹文档**：小模型任务边界 → [MODEL-CAPABILITY-LEDGER-DESIGN.md](./MODEL-CAPABILITY-LEDGER-DESIGN.md) 第 0 章；六层路由嵌套权限 → [REQUEST-LIFECYCLE.md](./REQUEST-LIFECYCLE.md) 2.9 节；问题台账 → [LIFECYCLE-GAPS.md](./LIFECYCLE-GAPS.md)。
> **撰写原则**：每条条文锚定一个真实失败模式（G/EXAM/F/复考题号）；边界清晰、无失败、无冲突的机制 ≤3 句话；不为咬合而咬合、不为漂亮而写章程——holo 的一切工作都是为了解决问题。
> **仲裁规则裁定权**：机制重叠区的仲裁规则（谁权限更高、用什么规则）最终裁定权在用户。未裁决条目标「⏳ 待裁决」（见第三节决策清单），成文规则一律可溯源到用户明确选择（第四节裁决记录）。

## 一、机制边界总册（四栏）

### L0 规则路由

- **能解决**：8 条硬规则零 token 直达；复考 0 误投。
- **不能解决**：规则表外的输入；文件名泛化归类。
- **边界界定**：设计取舍明文化——**「零 token 层」名不副实：文件名归类实际付 32 token LLM 微调用**（G-10，l0SkillRouter.ts:80-126），代价换来规则表无法覆盖的文件名泛化，且属小模型允许类 extract（账本 0.2 节）。
- **边界衔接**：未命中 → L0.5 接管；buildExplorePlan 探索规划属 reason-plan 越界豁免（账本 0.4 节）。

### L0.5 关键词快配

- **能解决**：单步 manifest 关键词快速命中（置信 hitRatio×1.5）。
- **不能解决**：多步 manifest——**结构性排除，仅单步参与**（G-12：最该快的重复多步劳动永远付全价 L2，快车道只服务琐碎任务）。
- **边界界定**：门 0.8/0.9 为启发式常量未经校准（G-15——「有数学外衣的直觉」）；歧义走消歧四策略，auto_pick 需 topScoreGap ≥ 0.15 且域信号匹配。
- **边界衔接**：miss/歧义未决 → L1/L2；与 L0 双命中且结果不同时信谁 → **O7 ⏳**。

### L1 单节点直调

- **能解决**：硬编码 2 条规则命中时的单节点管道直调。
- **不能解决**：规则外的一切。
- **边界界定**：**近乎死层**——硬编码 2 条规则（l0SkillRouter.ts:473-519），绝大多数请求穿透，六层漏斗实际是四层（G-11）；门 0.6/margin 0.10 未经校准（G-15）。此为已知取舍，非故障。
- **边界衔接**：miss → L2；被外层复用时按路由章程规则二仲裁（越外层调用权限越高，L1 规则照常服务两层）。

### L2 RaaP 匹配

- **能解决**：manifest 混合检索（向量+关键词 RRF 融合）；A3/P0-A inputForm 门控后复考路由误投 8→0。
- **不能解决**：语义近似但输入形态不符（inputForm reject）；无 manifest 覆盖的任务。
- **边界界定**：green 0.95/margin 0.10 未经校准（G-15）；L2 内 keyword_extract 改写重试是一次自救（kernels/default/index.ts:391，章程规则一登记）。
- **边界衔接**：miss → L3；L2 改写与 promptTranslator_intent 对同一输入的改写覆盖关系 → **O3 ⏳**。

### L3 LLM 仲裁

- **能解决**：多候选选号（maxTokens 128、#N 短输出可硬校验、失败可回退）——小模型允许类 select。
- **不能解决**：无候选可仲裁；仲裁失败的兜底判断。
- **边界界定**：命中置信恒 0.5（诚实下界）；仲裁前 inputForm 确定性预过滤（P0-A，toolRetrieval.ts:812-823，章程规则一登记）；离线走规则引擎降级。
- **边界衔接**：miss → L4。

### L4 探索模式

- **能解决**：文件场景复用规则；单步 llm_generate 直答；无 shell 自动执行。
- **不能解决**：复杂多步规划——探索规划打给小模型属 reason-plan 红线越界（buildExplorePlan 豁免登记，账本 0.4 节）。
- **边界界定**：最外层兜底；规划豁免的清退方向为规则化规划/账本升级路径（Phase C/D）。
- **边界衔接**：失败/miss → A4 兜底直答。

### 消费者上下文（macroExecutor 步骤间传递）

- **能解决**：step_N_result 步骤间结果传递。
- **不能解决**：全文档分析。
- **边界界定**：**按消费者 tier 截断：nano:300 / mini:600 / standard:800 / pro:2000 字符**（macroExecutor.ts:376-378）——S1 读入 12000 字财报，S2 只见前 800 字，即全文档的 6.7%（**G-1 明文承认**）。无任何机制检测或告知此信息瓶颈；结构性解法在 Phase D（map-reduce）。
- **边界衔接**：**无接管方——截断后信息对本流水线永久丢失**（孤儿边界，见第五节咬合校验 BC-1）。

### FactGuard

- **能解决**：金额/日期/百分比/编号/人名幻觉实体拦截；critical → 人工裁决暂停点（fail-closed）、minor → 自动替换。
- **不能解决**：**ground truth 只取 contextText 前 5000 字**（macroExecutor.ts:519，G-3）——文档后半的金额/日期不在保护范围内；与 G-1 叠加成最坏组合：模型看不全（可能编数字）、FactGuard 也看不全（编了不拦）；且仅覆盖 targetRoles 含 finance/legal/hr 的 manifest。
- **边界界定**：生成时硬闸（前置提 ground truth + 后置核验）；fail 方向按代价不对称（critical fail-closed）。
- **边界衔接**：与双引擎审计在「输出质量把关」重叠 → **O1 ⏳**（候选：时序切分——FactGuard 管生成时、审计管执行前动作）。

### 双引擎审计（dualEngineValidator）

- **能解决**：高危动作执行前拦截（intent_match/parameter_sane/risk_level 三字段）；审核器自身故障 = 阻断态（fail-closed）。
- **不能解决**：**审计与被审计同源**（都是同一小模型，CORE-ANALYSIS 证据 7）；审计 prompt 看不到文件内容只看意图与路径；本地低危读操作费效倒挂——read_file 付 5000t 审核调用，比动作贵一个数量级，缓存 key 含 targetFile 路径一换即 miss（**G-6**）。
- **边界界定**：isHighRisk 短路不调 LLM；shell_exec 收窄为写操作/危险 URL/敏感路径（P1-19）。属 judge 红线越界豁免（账本 0.4 节），清退方向 = G-6 审计重构。
- **边界衔接**：与 FactGuard 重叠 → **O1 ⏳**；与 deliverableCheck 在「完成判定」重叠 → **O2 ⏳**。

### 熔断器 / 重试

- **能解决**：3 次失败 open、冷却 30s、期满返还重试预算；可降级错误走降级链。
- **不能解决**：**短暂掉线误判**（探测失败 TTL 60s，providerChain.ts:11）；每请求实际最多 1 次自动重试（递归关闭 retryOnFailure，apiStore.ts:644-648/845-849）；anthropic 非流式硬编码 max_tokens 4096（**G-9**）。
- **边界界定**：AbortError/401/403/404 → 不可降级；5xx/429/timeout/网络类 → 可降级。
- **边界衔接**：与 M20 降级链都触发时的执行次序 → **O8 ⏳**。

### 执行指纹缓存

- **能解决**：auto-compile 晋级（10 次 + 真实执行率 ≥0.8）后编译态路径复用；脏步沿依赖 BFS 下传判脏。
- **不能解决**：**重启失忆**——持久化只存 resultHashes，重载后 results 清零，复用资产一重启清零重攒（G-13）；**零容错**——输入差一字（"Q3"改"三季度"）即整体 miss（G-14）；副作用步骤结果永不入缓存（P1-15）。
- **边界界定**：容量 50 FIFO；与语义缓存是两套独立命中判定，不一致时以谁为准 → **O4 ⏳**。
- **边界衔接**：miss → 全价执行。

### 语义缓存

- **能解决**：精确/语义双键命中免调用（自适应阈值 0.80–0.95）；命中 usage 全 0 记账（复考 R3+R4 重复任务 2s 秒回实证）。
- **不能解决**：带 tools 流量、>5 消息长上下文。
- **边界界定**：容量 500、TTL 24h；与指纹缓存命中判定相互独立 → **O4 ⏳**。
- **边界衔接**：miss → smartRoute。

### 偏好注入

- **能解决**：用户手动偏好经 system 前缀注入主路径（A3/P0-C；复考 R1 实证：偏好生效且隔离对照通过）。
- **不能解决**：自动隐式蒸馏（从反馈/纠正行为中学偏好——未实现，G-16 留 P2）；exam/benchmark 隔离流量不注入。
- **边界界定**：按 taskType 门控；结构化输出任务跳过；防重复注入。
- **边界衔接**：与竞争 EMA 信号方向冲突时的权重 → **O5 ⏳**。

### 竞争 EMA（M16）

- **能解决**：胜者 EMA=1.0、步骤失败 0.0、下轮负反馈 0.2 的质量信号结算；败者影子评估零副作用铁律。
- **不能解决**：非竞争场景的质量评价。
- **边界界定**：结算只在成功呈现后；影子评估只读不写。
- **边界衔接**：与偏好注入冲突 → **O5 ⏳**。

### M20 降级链

- **能解决**：远程未就绪/熔断 open 时逐级降级到本地 Ollama；链尽报错（可用性边界由链调和而非单点）。
- **不能解决**：链上模型能力评估——models[0] 盲选、无归因（Phase A+B 靶心，G-7 引用不重复展开）。
- **边界界定**：探测 GET /api/tags 3s 超时；失败 TTL 60s、成功 300s。
- **边界衔接**：与熔断器都触发时的次序 → **O8 ⏳**。

### 超时阶梯（llmTimeouts）

- **能解决**：CPU 校准四档 60/150/240/300s、绝对上限 600s、scale 经设置页暴露（A3/P0-B 后**唯一**定义点，四接入点收敛）。
- **不能解决**：8192 档满额在 CPU 上不可达——超时只兜挂死，不等满额。
- **边界界定**：TimeoutError 带确定性文案供 errorClassifier 归类，不落入 unknown 雪球路径。~~双配置冲突~~ 已消解——A3/P0-B 后 llmTimeouts 为唯一定义点，scale 是同一阶梯的放大器而非竞争配置（原 O9 重叠剔除依据）。
- **边界衔接**：与各调用点的接线以 llmTimeouts 为准。

### 模型网关 tier 体系

- **能解决**：复杂度打分定预算档（maxTokens/temperature/步级超时/计价）；A3 后复考 0 误投。
- **不能解决**：**tier 从不切换真实模型**（REQUEST-LIFECYCLE 贯穿不变式 1）——pro 档的「高档」承诺是 token 预算不是能力升级（G-7，Phase A+B 认领）。
- **边界界定**：confidence = budgetCapped ? 0.6 : 0.9；模式白名单 zero 仅 nano、economy 仅 nano+mini。
- **边界衔接**：网关内关卡顺序（policy 闸 × 预算闸 × 熔断）→ **O6 顺延代码批**（观察闸门未建，无现行冲突）。

### 隔离架构（taskType 学习隔离）

- **能解决**：benchmark/exam 流量四表隔离（语义缓存、预算 block、ZOL 学习、record-cost）；流式两处补守卫后 8 处 recordOutcome 统一 isLearningIsolated 判定（G-17 已修，EXAM 批）。
- **边界界定**：污染边界的调和架构；两入口（非流式/流式）同口径。
- **边界衔接**：无重叠、无 ⏳ 项——边界最清晰的机制。

### deliverableCheck（假完成核验）

- **能解决**：三态核验（存在性/非空/相关性）拦截假完成（P1-D）；假成功清指纹防重放；fail-open 不阻断主流程。
- **不能解决**：内容质量评价（属 judge 红线，不做）；交付物正确性。
- **边界界定**：L0 收口 + 宏收口三接入点；失败回退直答。
- **边界衔接**：与双引擎审计在「任务是否真完成」上重叠 → **O2 ⏳**。

### ZOL 零 token 学习

- **能解决**：success/failure/overkill 三信号（H-3 后语义诚实：successRate 只算执行成败，overkillRate 单独驱动阈值）；每 20 次窗口触发阈值调整。
- **不能解决**：模型能力归因（那是账本的职责，Phase A+B）。
- **边界界定**：routingHistory 上限 500、7 天过期、持久化最近 100 条；隔离流量不学习。
- **边界衔接**：阈值调整结果反哺 smartRoute 门值。

## 二、架构调和总纲

每个编排架构回答三问：**调和哪些边界冲突？用什么规则裁决？锚点在哪段代码？**

| 调和架构 | 调和的边界冲突 | 裁决规则 | 代码锚点 |
|---|---|---|---|
| 六层漏斗编排核 | 路由边界：哪层接手请求 | 内层优先、外层兜底；层序即仲裁序（用户已裁决，REQUEST-LIFECYCLE 2.9 节规则零/一/二/三） | funnel.ts LAYER_ORDER |
| 模型网关（apiStore 九道关） | 资源与资格边界：谁能花 token、花多少 | 关卡顺序即边界优先级（O6 ⏳ 顺延代码批——观察闸门建成后再定 policy 闸位置） | apiStore.chatCompletion |
| M20 降级链 | 可用性边界：模型/端点不可用 | 链序降级，链尽报错；与熔断并发的次序 → O8 ⏳ | findDegradedTarget |
| 学习回路（feedbackStore/EMA/fingerprint） | 质量边界：哪次结果可信可学习 | 隔离流量不学习；偏好 × EMA 信号冲突裁决 → O5 ⏳ | feedbackStore |
| 隔离架构（taskType 学习隔离） | 污染边界：考试/压测流量不得污染生产 | isLearningIsolated 双闸同口径（G-17 已修，事实登记） | apiStore 双入口 |

**调和总则**：

1. **每条边界必须有唯一接管方**（无孤儿边界——孤儿边界是故障源，不是美学缺陷）；
2. 边界冲突时更内层/更便宜机制先声明边界，外层架构兜底裁决；
3. 裁决规则必须代码化锚点——文档与代码不一致时以代码为准并开 G 条目；
4. **机制级重叠仲裁规则的最终裁定权在用户**（第四节裁决记录可追溯，build agent 无权自行裁定）；
5. 章程的存在理由是解决问题——条文失效或问题消失时条文应删除而非供奉。

## 三、重叠区仲裁决策清单（⏳ 待用户裁决）

每条格式：**问题**（今天造成过什么失败/风险）→ **重叠双方与场景** → **候选仲裁规则** → **不裁决的后果**。裁决后填写第四节记录并回填第一节对应条目。

| # | 问题（失败/风险） | 重叠双方与场景 | 候选仲裁规则 | 不裁决的后果 |
|---|---|---|---|---|
| O1 | 三重把关全盲区叠加：模型看不全（G-1）+ FactGuard 看不全（G-3）+ 审计看不到文件内容（G-6）；审计与被审计同源（证据 7） | FactGuard（生成时硬闸）× 双引擎审计（执行前动作审计）——「输出质量」双把关语义未定 | A 时序切分：FactGuard 管生成时输出、审计管执行前动作，各管一段互不重叠（现状的事实描述）；B 审计权限更高：高危动作审计先行，FactGuard 降为补充；C FactGuard 权限更高：生成时拦截优先，审计收窄为低危抽查 | 双方边界模糊，G-3/G-6 修复时不知往哪边收 |
| O2 | P1-D 假完成实证在先；两个「完成判官」可能打架 | deliverableCheck（三态硬核验）× 双引擎审计——「任务是否真完成」判定 | A deliverableCheck 权限更高：完成判定以硬核验为准，审计只管过程动作不判完成；B 从严合并：任一判官否决即不完成；C 分层：deliverableCheck 管宏收口、审计管步骤级 | 修复 G-6 收窄审计范围时可能误伤完成判定 |
| O3 | 同一输入被两处改写，覆盖关系未定义 | L2 keyword_extract 改写重试（层内自救）× promptTranslator_intent（意图翻译） | A intent 翻译先行且权威，L2 改写仅在 L2 内部 miss 自救、不外溢；B L2 改写结果可覆盖 intent 翻译；C 禁止同请求内双改写生效（先到先得） | 改写语义漂移，复考「答非所问」类问题归因困难 |
| O4 | 两套缓存命中判定独立，判定不一致时行为未定 | 语义缓存（对话级）× 执行指纹缓存（宏执行级） | A 维持独立互不覆盖（服务不同层，现状）；B 指纹缓存权限更高（执行级复用优先）；C 语义缓存权限更高 | 边界已天然分层（对话 vs 宏），不裁决即维持现状，风险低 |
