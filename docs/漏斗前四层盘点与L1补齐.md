## 二、L1 缺口明细与补齐

### 2.1 缺口（补齐前）

`L1_TOOLS` 声明 6 节点（`src\data\topology.ts`；`README.md:65` 一一对应），但 `checkL1Capability` 只产出 4 个 nodeId（`l0SkillRouter.ts:637/669/685/691`）：

| # | 节点 | 职责 | 路由层（补齐前） | 执行侧 handler |
|---|---|---|---|---|
| 1 | `l1-knowledge-feeder` 知识库投喂员 | 转化为 AI 可检索的本地知识库 | ✅ | ✅ `pipelineExecutor.ts:157` |
| 2 | `l1-model-gateway` 模型网关 | 模型探测与切换 | ✅ | ✅ `:158` |
| 3 | `l1-task-translator` 任务翻译官 | 大白话 → 结构化 Prompt 链 | ❌ | ✅ `:159`（`compileToChain`） |
| 4 | `l1-pipeline-builder` 流水线搭建台 | 多步骤 → 流程图编排 | ❌ | ✅ `:160`（`compileToChain`） |
| 5 | `l1-workspace-memory` 工作区记忆体 | 项目历史上下文、支持追问 | ❌ | ✅ `:161`（`getContextWindow`） |
| 6 | `l1-result-beautifier` 结果美化师 | Markdown → Word/PPT/邮件格式 | ❌ | ✅ `:162`（`beautify`） |

**性质**：半接——执行侧 6 handler 全部注册（`registerHandler` 6 次调用，`pipelineExecutor.ts:157-162`），路由侧只认 4 个。缺口严重度有数据背书：4 个"死节点"正是 L2 清单高频依赖的 `routing.requiredL1`——`l1-task-translator` 被 **20** 处引用、`l1-result-beautifier` **11** 处、`l1-pipeline-builder` **4** 处、`l1-workspace-memory` **3** 处。`l1Capabilities.ts` 早已登记它们为权威能力，但**登记 ≠ 路由可达**。

### 2.2 补齐方式

在 `checkL1Capability` 的 `l1Rules` 数组（`src\services\l0SkillRouter.ts`）追加 4 条规则。**产出逻辑与循环体一行不改**——只加规则数据，与现有 2 条能力同范式。

| 新节点 | 触发词（2-3 词短表） | 禁词（防劫持 L2） |
|---|---|---|
| `l1-task-translator` | 拆解 / 执行步骤 / 任务分解 | 文档 / 文件 / docx / 合同 / 审查 / 风险 / 报告 / 周报 / xlsx / ppt / 表格 / 清单 |
| `l1-result-beautifier` | 排版 / 美化 / 渲染成 | 创建 / 新建 / 写文件 / 删除 / 移动 / 审查 / 合同 / 风险 / 周报 / 会议纪要 |
| `l1-workspace-memory` | 还记得 / 之前聊过 / 历史记录 | 创建 / 新建 / 写入 / 删除 / 审查 / 合同 |
| `l1-pipeline-builder` | 编排 / 流水线 / 自动化流程 | 审查 / 合同 / 报告 / 风险 |

**关键词表为什么必须短**：confidence 公式 = `min(matchedKw / keywords.length × 2, 0.9)`。3 词表下单次命中即 0.667 ≥ 门 0.6；若堆到 9-10 词，单次命中只有 0.2，规则将**永不触发**（这是初版设计的缺陷，执行时修正）。

**产出形态（2026-09-30 深化后已更新）**：补齐分两步——先让 L1 从 2 能力到 6 能力**路由可达**；再让四节点的计划步骤直接挂各自的 `l1-*` 工具名，由 `macroExecutor.callToolDirectWithTier` 的 L1 分派调用 `pipelineExecutor` 里已注册的 handler（不再是统一 `llm_generate`）。分派实现：`getHandler(name)` → 构造 `NodeHandlerContext`（gateway 经 `llm:get-gateway`、memory/knowledge adapter）→ 输出归一化；四个 `l1-*` 已登记进 `toolRegistry.NATIVE_TOOL_NAMES` 以走 `isAllNative` 快路径。
