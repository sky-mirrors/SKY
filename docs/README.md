## 这套文档是什么

SKY 的**唯一权威文档集**。在此之前的 30 余份文档（架构分析、审计报告、机制盘点、快照、手册）已全部删除：它们系统性滞后于代码，且互相矛盾（同一文件内正文与归档表给出相反结论）。

本套文档的替代做法是：**拆分册 + 每条断言回代码取证**。

- 每册按**一个关注点**组织，可单独阅读、单独更新。
- 每条「当前状态」断言都带 `file:line` 或可直接执行的命令。
- 复核不了的条目**标注为 `[未证实]`**，绝不照抄。

## 核实等级标记（全文通用）

| 标记 | 含义 | 门槛 |
|---|---|---|
| `[已复核]` | 用 `grep` / `read_file` 回到代码核对过 | 附 `文件:行` |
| `[实测]` | 在**运行中的应用**里实测（CDP 探针，脚本在 `.rivet/scratch/`） | 附命令或探针名 |
| `[未证实]` | 来自历史文档或二手转述，**本轮未回代码** | 引用前必须复核 |
| `[设计]` | 文档化的设计意图，**不等于已实现** | 不得当作现状引用 |

**看到 `[已复核]` 仍可存疑的地方请直接回代码**——本项目历史上多次出现「已修 / 未修」标记与代码相反的情况。

## 维护约定（硬规则）

1. **代码改了，改这里**。不要新建文档、不要在别处写第二份口径。改哪一块，改哪一册。
2. **每条现状断言带锚点**。写「XX 在 `src\services\<模块>.ts:<行号>`」而不是「XX 在某个服务里」。改动导致行号漂移时，同步更新引用它的分册。
3. **数字必须来自实测**。测试用例数、包大小、覆盖率——写进文档前先跑命令拿输出，不沿用上一版。
4. **删掉被取代的内容**。分册里不留「旧口径 + 新口径」并列，只留当前口径。
5. **交付时同步**。改了某机制的代码，同一个提交里把对应分册更新掉（代码与文档同批提交）。
