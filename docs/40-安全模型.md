## 开源发布审计 `[已复核 2026-10-10]`

`scripts\oss-audit.mjs` 是发布前 / 出网前的机密门禁。**不依赖任何 CI 服务也能力跑**（纯 node + git 子进程）。

| 规则 | 查什么 | 何时能查到 |
|---|---|---|
| A | 密钥前缀 / 私钥块 / 已知 token 形态（`sk-` / `ghp_` / `AKIA` / `-----BEGIN … PRIVATE KEY` …） | **仅当前跟踪文件** |
| B | 赋值式密钥（`api_key = "…"`） | **仅当前跟踪文件** |
| C1 / C2 | 含本机用户名的绝对路径（C1 可 `--fix` 脱敏，只动当前机器用户名） | 当前跟踪文件 |
| D / E / F | 凭据类扩展名 / 运行时目录 / 产物文件被跟踪 | 当前跟踪文件清单 |
| G | 历史里的可疑**文件名**（`.env` / `.pem` / `id_rsa` …） | `--history` |
| **H** | 历史 blob **内容**里的密钥形态 | `--history` |

**规则 H 是关键补强**：A/B 只扫当前跟踪文件，文件一删就再也看不到——而真实泄漏恰恰发生在"已删除文件的历史版本"里。2026-10-10 发现 DeepSeek key 随 `test\e2e\*.spec.ts` 进了初始提交 `059ea9d`、文件后于 `1aeba57` 删除，密钥却仍在公开历史与 tag `v0.1.0` 中。G 只查文件名同样漏掉它，H 才检得到。

### 已知命中白名单

`scripts\oss-audit-history-whitelist.json` 登记**已发生且已接受**的历史命中——**只存 sha256，绝不存明文**（该文件本身也在公开仓库里）。白名单项降级为提示（不阻塞），未登记的命中一律阻塞。当前条目为空——2026-10-10 的那次泄漏已用 `git filter-repo` 重写历史清除（见 `SECURITY.md`「凭证与机密」）。

### 发现历史泄漏时的处置顺序

1. **先吊销并轮换凭证**——无论是否清洗历史，这一步必做。
2. **再判断能否清洗**：仓库**未被 fork / 镜像 / 爬取** → `git filter-repo --replace-text` 重写 + force push（含 tag），有效；**已被外部复制** → 清洗收益归零（对方克隆里仍有），只能靠轮换兜底。
3. **验证**：`node scripts/oss-audit.mjs --history` 应报 0 命中；有条件时从远端**全新克隆**再扫一遍（本地扫描看不到 GitHub 侧的旧对象）。
4. 仍存疑则联系 GitHub Support 触发 GC——force push 后旧对象在一段时间内仍可能被**已知 SHA** 访问。
