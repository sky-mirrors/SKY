将后端强大的125节点拓扑，映射到*仅一个透明立方体+太空背景的客户端
一、 视觉层：太空中的“全息星图”（零UI文字干扰）
立方体框架：使用极细的淡蓝色全息线框（发光强度0.3），仅勾勒出5×5×5的网格交点（共125个节点）。线框在旋转时带有微弱的多普勒频移效果——靠近用户的节点线框变亮，远离的变暗，增强太空纵深感。
节点视觉编码（完全依靠“星辰”区分层级）：
L0 用户本体一颗静止不动的纯白脉冲星（缓慢呼吸光晕），位于正中心。
L1 6个核心工具：6颗金色恒星，带有固定的十字星光衍射芒，位于距离中心1个单位的面心处。
L2 20个自选/系统填充工具：20颗蓝色/青色行星，带有环绕的细小微粒轨道环，位于距离中心√2（棱心）和√3（角心）处。其中用户手动选中的20个显示为亮青色，系统自动填充的显示为暗青色。
L3 98个社区工具：98颗不断缓慢漂移的流星/星尘，位于最外表面（距离中心2个单位），它们的光点极其微小，且颜色随社区热度在紫-绿之间渐变（热度高偏紫）。
 二、 交互层：纯粹的鼠标与空间直觉（无按钮、无菜单）
规定右键拖动改变视角，为了不让手指在三维空间中迷路，视角与选择完全解耦：
| 鼠标操作          | 系统响应（客户端逻辑）                                                                                                                                          | 后端对应动作                     |
| :---                  | :---                                                                                                                                                                         | :---                                    |
| 右键按住并拖动| 太空视角旋转（轨道控制器）。立方体整体旋转，背景星域随之流动。此操作不选中任何工具，仅用于巡视数字宇宙。 | 无后端调用，纯GPU渲染。 |
| 滚轮滚动          | 视角景深推进/拉远。滚轮向前，镜头穿过外围星尘，聚焦于核心6颗金色恒星；滚轮向后，拉远看到整个125节点的全貌。 | 触发L3社区工具的刷新预加载（拉远时后台拉取最新社区热度数据）。 |
| 左键单击节点 | 引力聚焦。被点击的节点会短暂放大并带有“引力波”扩散特效，同时该工具立即在客户端右下角（或系统通知区）以极简文字浮窗显示名称（例如仅显示“语境卫士”四个字）。 | 启动该工具的本地离线进程（或唤醒快照）。 |
| 左键按住L2节点，拖拽至L1节点 | 超新星爆发特效。被拖拽的青色行星拖出光轨，撞向金色恒星时发生短暂闪白。两颗节点互换视觉层级（原L1工具降维至L2空缺位）。 | 执行“常用工具嵌入核心”的配置写入。 |
| 鼠标悬停（不点击）停留1.5秒 | 星尘连线。悬停的节点自动向周围相邻（曼哈顿距离为1）的节点发射出半透明的数据流线，直观展示该工具与哪些邻接工具存在“结合性”关系。 | 后端读取该节点的关联映射表并渲染。 |
三、 针对“20个用户自选”的客户端特别表达
客户端必须区分这两种状态，但绝不破坏“纯太空”的美感：
系统自动填充（默认）：20个L2节点呈现为暗青色行星，轨道环转速均匀。右键悬停它们时，仅显示工具名，不提供删除按钮。
用户手动锁定（自选）：当用户在设置界面的“20格清单”中勾选了自己偏好的工具后，对应L2节点会从暗青渐变为亮青色，且行星轨道环停止转动（代表“已被锚定”），同时该星球表面会生成一颗极其微小的白色信标灯，让用户一眼能在20颗星中认出“这是我的专属配置”。
 四、 社区L3自动工具的“潮汐”视觉动态
为了让98个社区自动工具“活”起来，但又不干扰用户操作：
潮汐流：外围98颗星尘并不是静止的，它们会沿着立方体表面的经纬线网格缓慢漂移（速度极慢，周期约3分钟绕一圈）。当某颗星尘漂移到距离用户当前正在使用的L1核心工具最近的面心方位时，它会短暂闪烁一下，表示“此社区工具与您当前工作流高度相关”。
淘汰与新生：如果某颗外围星尘因30天未使用而被社区淘汰，它会模拟恒星坍缩动画——瞬间收缩为一个红点然后消失；新的社区工具入驻时，会以超新星诞生动画——从一片星云中凝结成星尘。整个过程零弹窗、零提示，维持沉浸感。
五、 默认初始视角（首次打开软件）
既然背景是太空，用户第一次打开时，不应看到全部125个点（那会让人密集恐惧）。初始视角设定为：
镜头拉近：默认只呈现中心1个白星 + 6个金色恒星 + 与Z轴正方向（头顶）相邻的3个暗青色L2行星。
引导暗示：太空背景中，有一条极淡的银河旋臂光带，恰好穿过原点和头顶那颗L2行星，暗示用户“滚轮向后拉，能看到更多星辰”。
右键拖动第一下：太空背景中的遥远星系会产生轻微的视差，让用户立刻感知到自己拥有对这片宇宙的绝对控制权。
六、 对抗“误操作”的设计
由于只有鼠标交互，必须防止拖拽改变视角时误触工具：
设定交互死区：鼠标在拖动过程中，如果移动速度超过阈值（即快速甩动），系统判定为“视角切换”，不触发任何节点的悬停或点击事件。
只有鼠标静止或缓慢移动时，悬停/点击事件才生效。这确保了在太空“巡视”时的丝滑手感。




1. 目标人群：企业办公者（文员、项目经理、财务、人事、法务等非技术岗）。
2. 模型管家：必须支持接入本地已部署的 API（兼容 OpenAI 格式的端点，如 vLLM、LocalAI、Ollama 开启的 OpenAI 兼容服务等）。
3. 交互方式：坚守鼠标拖拽+点击，纯星图操控，语音仅作为可选的辅助快捷键，不做主交互。
基于此，这套立方体不再是“通用 AI 工具箱”，而是一个明确的 企业本地 AI 工作流控制台。接下来将这一定位正式注入 L1 六大核心

L2（20个自选/系统填充）——为企业办公预制“技能包”
既然目标锁定企业办公者，L2 的 20 个位置不再空置。系统会在首次启动时，根据用户选择的“岗位类型”（如人事/财务/销售/法务），自动向 L2 的棱心和角心填充已经配置好的“工作流模板”，用户只需点击执行。

示例（财务岗首次启动自动填充的 3 个 L2 节点）：
棱心节点（知识库 + 翻译官) → 财报风险一句话解读：拖入 PDF 财报，自动输出本季度现金流下降 15%，主要原因为库存积压这类一句话总结。
角心节点（知识库 + 翻译官 + 美化师） → 报销单合规检查：扫描报销单图片，提取金额、日期、事由，自动判断是否符合公司常理范围，并生成带颜色标记的审核意见。
棱心节点（流水线 + 记忆体） → 周报自动草稿：读取本周所有编辑过的文档和邮件，按“项目进展 / 遇到的问题 / 下周计划”三段式生成周报草稿。
剩余的 17 个节点，系统会根据用户后续的实际操作，动态从社区 L3 升级上来，或者由用户从社区模板市场中手动“订阅”并填入。

企业办公者的首次 5 步无痛旅程（验证设计是否合理）

Step 1：安装后启动
看到太空中的透明立方体，默认近景只显示中心白星 + 6 颗金色恒星。右侧（X轴正向）的“知识库投喂员”闪烁着微弱呼吸光，暗示“请拖入文件”。
Step 2：绑定本地 AI（唯一的一次“技术配置”）
右键旋转立方体，找到负 X 轴方向的“模型网关”（金色恒星），双击它（这是全局唯一进入设置的动作）。
弹出一个极简的透明输入框（非阻塞窗口）：“请输入本地 API 地址”。用户粘贴 `http://127.0.0.1:1234/v1`，点击确认。网关自动探测并显示可用模型名称（如 `qwen2.5-7b`），用户选择一个默认模型。配置结束，全程不需要打开命令行。
Step 3：投喂第一份文件（触发 L2 自动推荐）
用户从电脑文件夹中，左键按住一份年度总结 Word 文档，拖拽至“知识库投喂员”节点。节点发出涟漪光效，文档被消化。
-此时，立方体外部靠近该节点的 3~4 个 L2 青色行星突然变亮并轻微震动，表示“检测到可用技能包”，例如“提炼要点”、“翻译英文版”、“生成PPT大纲”。
Step 4：拖拽完成复杂任务（鼠标连线）
用户从 L2 中选择那颗代表“提炼要点”的行星，左键按住它，拖拽到“结果美化师”（Z轴负向）节点。松开鼠标，系统自动执行：投喂员提供文档 → 翻译官拆解任务 → 网关调用本地模型 → 美化师输出。
右下角浮窗显示：“提炼已完成，点击查看”。用户点击，一份带层级标题的摘要直接展示。

Step 5：固化常用工作流（嵌入核心）
用户觉得这个流程特别好用，于是将“提炼要点”这颗 L2 行星，直接拖拽到“知识库投喂员”旁边的空余位置（作为附属工具）。系统提示“已嵌入核心，下次可直接一键执行”。从此，这颗行星常亮在核心层附近。

2. 模型网关对接本地 API 的容错机制：
如果用户填写的 API 地址不可达（比如没启动本地服务），立方体如何处理？
自动切换为降级模式，提示检测不到 AI 大脑，仅可使用本地规则引擎（如关键词提取、格式转换），部分依赖 AI 的 L2 节点暂时变暗，但不影响非 AI 工具使用。
