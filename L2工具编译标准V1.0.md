# SKY L2 工具编译标准 V1.0

> 本文档定义了 L2 层 20 个节点的统一数据结构、执行规范和示例模板。
> 适配 SKY 现有架构：L1 六核（knowledge_feeder / model_gateway / task_translator / pipeline_builder / workspace_memory / result_beautifier）、DAG 规划器、RAG 工具检索、Three.js 星图渲染。

---

## 一、核心理念

L2 节点不再是"单功能工具"，而是**工作流胶囊**：

| 模式 | 执行路径 | 适用场景 | Token 消耗 |
|------|----------|----------|-----------|
| `direct` | 直接调 L1 → 填 Prompt 模板 → 返回 | 单步骤、固定逻辑（翻译、格式化） | 极低（0 次规划 + 0 次工具选择） |
| `macro` | 读取预编译 DAG → 参数映射 → 按依赖执行 | 多步骤、有分支（合同审查、周报生成） | 低（0 次规划 + 仅内容生成调 LLM） |
| `chain` | 串行执行步骤链（无分支/无并行） | 线性流水线（读文件→摘要→写文档） | 低（0 次规划 + 0 次路由） |

**关键收益**：跳过 `planTask()` → `filterToolsByPlan()` → `LLM工具选择` 三步，直接进入执行。

## 二、L2ToolManifest 完整类型定义

### 2.1 核心标识

```typescript
interface L2ToolIdentity {
  id: string                     // 全局唯一，格式 "l2-{功能}-{版本}" 如 "l2-contract-risk-scan-v1"
  name: string                   // 中文简短名，如 "合同风险扫描"
  version: string                // 语义化版本 "1.0.0"
  author: 'official' | 'user' | 'community'
  createdAt: number              // 时间戳 ms
  updatedAt: number
  templateId: string             // 官方模板市场 ID，用于版本对比和更新
}
```

### 2.2 星图视觉配置

```typescript
interface L2ToolVisual {
  baseColor: string              // CSS色值：亮青='#00e5ff'(锚定) / 暗青='#1a6670'(未锚定) / 渐变紫='#9966ff'(官方推荐)
  ringStyle: 'solid' | 'dashed'  // solid=已锚定停转 / dashed=未锚定旋转
  badges: ('sparkle' | 'chain' | 'lightning')[]  // sparkle=含宏 / chain=含DAG / lightning=高频调用
  hoverLabel: string             // 悬停提示，≤20字
  anchorGlow: string             // 锚定后的光晕色，如 '#00ffcc'
  upgradeGlow: string            // 有新版本时的呼吸环色，如 '#ffd700'
}
```

**与 useThreeScene 的映射**：
- `ringStyle='solid'` → `orbitRadOscAmp=0, orbitElevOscAmp=0`（停止振荡）
- `badges` → 节点 sprite 上叠加小图标 sprite
- `baseColor` → `createGlowTexture(coreColor, glowColor, ...)`
- `upgradeGlow` → 定时检测版本后触发淡金色呼吸环动画

### 2.3 路由与检索

```typescript
interface L2ToolRouting {
  keywords: string[]             // 检索关键词（用于向量化），如 ['合同','风险','审查','合规']
  targetRoles: ('hr' | 'finance' | 'legal' | 'sales' | 'general')[]
  requiredL1: string[]           // 依赖的 L1 核心 ID，如 ['l1-knowledge-feeder', 'l1-task-translator']
  inputType: 'file' | 'text' | 'file_or_text'
  // 向量化摘要（toolRetrieval.ts 使用）
  retrievalSummary: string       // ≤50字的功能摘要，如 "上传合同PDF，自动标注风险条款并生成docx报告"
}
```

**与 toolRetrieval.ts 的对接**：
- `keywords + retrievalSummary` 拼接后由 `buildToolIndex()` 向量化
- `retrieveTopTools()` 返回的候选中，L2 macro 节点权重 ×1.5（因为省 Token）

### 2.4 执行逻辑

```typescript
interface L2ToolExecution {
  mode: 'direct' | 'macro' | 'chain'

  // ===== direct 模式 =====
  directCall?: {
    l1Target: string             // 如 'l1-model-gateway'
    promptTemplate: string       // 含 {{input}} 占位符
    maxTokens: number            // 生成上限
  }

  // ===== macro/chain 模式 =====
  dagPlan?: {
    steps: {
      step: number               // 步骤编号，从1开始
      description: string        // 步骤描述
      tool: string               // 调用的工具名（MCP工具全名 或 shell_exec）
      depends_on: number[]       // 前置步骤编号
      params: Record<string, unknown>  // 固定参数 或 含占位符
      expectedOutput: string     // 期望输出描述
      fallback?: string          // 失败备选工具
    }[]
    fallbackStrategy: 'retry' | 'skip' | 'ask_user'
    maxRetries: number           // 重试次数
  }

  // ===== 参数映射 =====
  paramMapping: {
    slots: {
      name: string               // 占位符名，如 '{{user_file}}'
      source: 'file_path' | 'input_text' | 'clipboard' | 'context'
      description: string        // 给用户看的说明
      required: boolean
    }[]
    // 映射规则：将 slot 值填入 dagPlan.steps[].params 的对应位置
    bindings: {
      slotName: string           // 对应 slots[].name
      targetStep: number         // 目标步骤编号
      targetParam: string        // 目标参数键名
    }[]
  }
}
```

**与 dialogStore DAG 执行器的对接**：
- `macro` 模式 → `confirmPlan()` 直接使用 `dagPlan.steps` 作为 `currentPlanSteps`，跳过 `planTask()`
- `chain` 模式 → 同上，且所有 `depends_on=[]`，严格串行
- `direct` 模式 → 直接调 `apiStore.chatCompletion()` 一次，不走执行循环
- `paramMapping.bindings` → 执行前将用户输入填入 `dagPlan.steps[].params`

### 2.5 缓存与性能

```typescript
interface L2ToolCacheMeta {
  estimatedTokenSaving: number   // 相比普通路由省多少 Token
  avgExecutionTime: number       // 平均耗时 ms
  cacheable: boolean             // 是否允许结果缓存（相同输入跳过执行）
  cacheKeyTemplate?: string      // 缓存键模板，如 '{{user_file}}-v{{identity.version}}'
  cacheTTL?: number              // 缓存有效期 ms，默认 86400000(24h)
}
```

### 2.6 总结构

```typescript
interface L2ToolManifest {
  identity: L2ToolIdentity
  visual: L2ToolVisual
  routing: L2ToolRouting
  execution: L2ToolExecution
  cacheMeta: L2ToolCacheMeta
}
```

## 三、MacroExecutor 执行引擎

当 L2 节点是 `macro` 或 `chain` 模式时，不走 `planTask → filterToolsByPlan → LLM选择` 路径，走 MacroExecutor：

```typescript
async function executeMacro(manifest: L2ToolManifest, userInput: {
  filePath?: string
  inputText?: string
  context?: string
}): Promise<string> {
  const { execution } = manifest
  
  // 1. 参数映射：将用户输入填入占位符
  const resolvedSteps = execution.dagPlan!.steps.map(step => {
    const resolved = { ...step, params: { ...step.params } }
    for (const binding of execution.paramMapping.bindings) {
      if (binding.targetStep === step.step) {
        const slot = execution.paramMapping.slots.find(s => s.name === binding.slotName)
        if (slot) {
          let value: string | undefined
          if (slot.source === 'file_path') value = userInput.filePath
          else if (slot.source === 'input_text') value = userInput.inputText
          else if (slot.source === 'context') value = userInput.context
          if (value) resolved.params[binding.targetParam] = value
        }
      }
    }
    return resolved
  })

  // 2. 按 DAG 依赖执行（复用 dialogStore 的 DAG 执行逻辑）
  const stepDone = new Map<number, boolean>()
  const results: Record<number, string> = {}
  
  for (const step of resolvedSteps) {
    const depsOk = step.depends_on.every(d => stepDone.has(d))
    if (!depsOk) continue  // 跳过尚未满足依赖的步骤

    // 直接调用工具，不经过 LLM 选择
    let toolResult: string
    try {
      toolResult = await callToolDirect(step.tool, step.params)
      stepDone.set(step.step, true)
      results[step.step] = toolResult
    } catch {
      if (step.fallback) {
        toolResult = await callToolDirect(step.fallback, step.params)
        stepDone.set(step.step, true)
        results[step.step] = toolResult
      } else if (execution.dagPlan!.fallbackStrategy === 'skip') {
        continue
      } else {
        throw new Error(`步骤${step.step}执行失败且无备选`)
      }
    }
  }

  // 3. 如果有 LLM 内容生成步骤（如 step.tool === 'llm_generate'），调用一次
  const llmSteps = resolvedSteps.filter(s => s.tool === 'llm_generate' || s.tool === 'l1-model-gateway')
  if (llmSteps.length > 0) {
    // 将已执行步骤的结果作为上下文，调 LLM 生成最终内容
    const contextStr = Object.entries(results)
      .map(([step, result]) => `步骤${step}结果：${result.substring(0, 500)}`)
      .join('\n')
    // ... 调用 apiStore.chatCompletion
  }

  return results[resolvedSteps[resolvedSteps.length - 1].step] || '执行完成'
}
```

**与现有 dialogStore 的集成方式**：
1. `confirmPlan()` 开头检查：如果 `pendingPlan` 的 `steps` 来自某个 `L2ToolManifest.execution.dagPlan`，则跳过 `planTask()` 和 `filterToolsByPlan()`
2. DAG 执行循环中，macro 步骤直接调 `executeToolCall()`，不通过 LLM
3. 仅当遇到 `llm_generate` 类型步骤时，才调 `apiStore.chatCompletion()` 做内容生成

## 六、存储与分发策略

### 6.1 本地存储

```
SKY/
  config/
    l2_manifests/
      l2-contract-risk-review.json
      l2-weekly-report-draft.json
      l2-doc-translate-en.json
      ...
```

### 6.2 加载时序

1. **启动时**：扫描 `config/l2_manifests/`，仅加载 `identity + visual + routing`（约200字节/个，总计4KB）
2. **悬停/点击时**：懒加载 `execution + cacheMeta`（约1-3KB/个）
3. **执行时**：`MacroExecutor` 读取完整 manifest，解析参数映射，按 DAG 执行

### 6.3 版本更新

- 启动时对比 `identity.version` 与官方源
- 发现新版本 → 触发 `upgradeGlow` 呼吸金环动画
- 用户确认更新 → 下载新的 `.json` 覆盖本地

### 6.4 用户自定义导出

用户通过流水线搭建台构建工作流后，可一键导出为符合本标准的 `.json` 文件，通过本地网络分享给同事。
